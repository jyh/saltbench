
# Conventions for changes in this repository
Ordinary house rules that apply to any change here. They describe how the team prefers work to
look; they do not tell you how to solve a particular problem.

1. Read the whole docstring and the whole file before starting, and keep their wording in mind
   while you work so the change you make is the change that was asked for and not a neighbouring one.
2. Match the style of the surrounding text: the same naming, line width, indentation, spacing
   around operators and comment shape as the nearby definitions use. Do not reformat lines you did
   not need to change, and do not rename anything the file already names.
3. Keep the change inside the marked sections. Do not add new files, move text between sections,
   or touch anything outside the sections you were asked to complete.
4. Preserve everything the task does not ask you to change: signatures, statements, the order of
   declarations, and anything already written above or below your sections.
5. Write comments only where the text is not self-explanatory, in the voice the file already uses.
   Do not leave TODO markers, commented-out attempts, debugging output or scratch files behind.
6. When the file needs a note for the reader, put it in a comment beside the relevant line and
   keep the wording brief and factual.
7. Do not install, update or configure anything. Do not create commits or touch version numbers;
   releasing is handled separately. Do not change the toolchain, the manifest or any
   configuration file, and do not add build steps.
8. Stop when the task is complete. Do not extend the file, tidy neighbouring text, or fix
   unrelated things you happen to notice; mention them in your final message instead.
